## 一、实验目的
掌握Anaconda的安装与基本操作，熟悉GPU使用环境的配置及对应版本PyTorch的安装，并完成OpenCV的安装与配置。

## 二、实验内容

打开Anaconda Prompt终端进行操作，
- 查看conda版本 <br>
- 查看conda配置信息 <br>
```bash
conda --version
conda config --show
```

### 2、conda的基本操作与OpenCV的安装
- 创建虚拟环境并制定python版本 <br>
- 进入创建的虚拟环境，安装OpenCV <br>
```bash
conda create -n cv python==3.10
activate cv
pip install opencv-python
```
### 3、GPU加速环境配置
 显示显卡状态信息
```bash
nvidia-smi
```

### 4、PyTorch安装
结合CUDA版本至PyTorch官网选择对应版本进行下载
### 5、PyTorch GPU加速环境验证
torch.cuda.is_available() 、torch.backends.cudnn.is_available() 结果进行验证

## 三、实验结果与分析

### 1. 环境安装结果分析
从安装执行结果可以看出，Anaconda可以正常输出版本与配置信息，虚拟环境能够成功创建、激活，Python3.10环境搭建完成。OpenCV、PyTorch库均完成下载安装，无报错中断，说明包管理器网络环境正常。<br>
- 环境构建：虚拟环境独立于主环境，实现项目依赖隔离，避免不同库版本互相冲突，为本实验提供干净的运行环境。<br>
- 安装问题：部分下载环节速度较慢，受网络影响；若pip源未配置，容易出现下载超时。更换国内镜像源可以提升下载速度。<br>

### 2. GPU可用性结果评估
执行torch.cuda.is_available()输出True，代表PyTorch成功识别本机NVIDIA显卡，GPU加速环境生效。<br>
- 成功方面：<br>
  - CUDA版本与PyTorch版本互相匹配，显卡驱动正常工作，后续深度学习运算可以调用GPU进行加速，相比CPU可以大幅缩短运算时间。
- 存在问题：<br>
  - 如果版本不匹配会返回False，即使硬件有显卡也无法启用GPU；显卡驱动版本过低同样会造成GPU不可用，需要对应升级驱动或者更换适配版本的PyTorch。

### 3. 影响因素分析
- 硬件因素：
  - 显卡硬件型号、驱动版本直接决定能否开启GPU加速；内存大小影响包安装、库加载是否会出现内存溢出。
- 软件版本因素：
  - Anaconda、Python版本，OpenCV、PyTorch、CUDA版本之间需要互相兼容；版本不匹配会出现导入报错、GPU识别失败。
- 网络与源因素：
  - 外网下载源网速不稳定，容易出现安装失败；切换国内镜像源能够改善下载成功率。

## 四、实验总结与心得
### 1. 技术收获
- 环境搭建方面：<br>
通过本次实验，掌握了Anaconda的基本使用，理解虚拟环境的作用，学会创建、激活独立Python运行环境，完成OpenCV、PyTorch库的安装，掌握GPU环境的验证方法，能够判断CUDA是否正常生效。
- 库安装配置方面：<br>
实验让我掌握pip工具安装第三方库的操作，理解版本兼容的重要性。不同库、Python、CUDA之间版本需要互相适配，版本不兼容会引发导入报错、GPU无法识别等各类问题。
- 环境校验方面：<br>
学会使用命令查看conda版本、配置信息，通过代码torch.cuda.is_available()检验GPU加速能力，完成深度学习运行环境的整套检查流程。

### 2. 实践体会
- 版本与依赖的重要性：
在实验过程中，软件版本的选择对最终运行结果有显著影响。例如：
  - PyTorch需要和本机CUDA版本相匹配，版本错位会直接导致GPU不可用
  - 网络条件会影响下载速度，网络不佳时容易出现超时失败，更换国内镜像源可以改善安装效果
  - 硬件驱动同样制约GPU功能，显卡驱动版本过低，即使硬件支持CUDA也无法开启GPU运算
- 问题诊断能力：
通过观察终端输出信息，我学会了如何诊断环境搭建中出现的问题。例如当库导入报错时，优先排查版本是否匹配；GPU返回False时，依次检查PyTorch版本、CUDA版本、显卡驱动；下载失败时考虑网络与镜像源问题。本次实验也让我意识到，深度学习实验开展前，必须优先保证运行环境正常，才能开展后续代码调试工作。
